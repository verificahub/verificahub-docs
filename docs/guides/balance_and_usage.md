# Контроль баланса и статистики

Verificahub работает по предоплате (pay-as-you-go): за каждую инициированную проверку списывается стоимость по тарифу. Два метода помогают следить за расходами.

## Текущий баланс

```bash
curl https://api.verificahub.ru/v1/balance \
  -u api_key:api_secret
```

```json
{
  "balance": { "amount": 1500.0, "currency": "RUB" }
}
```

:::tip
Проверяйте баланс по расписанию и настройте оповещение, когда он опускается ниже порога — при нулевом балансе инициировать проверку не получится (ошибка `402`).
:::

## Статистика за период

`GET /v1/usage` возвращает сводку за диапазон дат: сколько проверок инициировано, сколько успешно, какова конверсия и сумма затрат.

```bash
curl "https://api.verificahub.ru/v1/usage?from=2026-06-01&to=2026-06-17" \
  -u api_key:api_secret
```

```json
{
  "from": "2026-06-01",
  "to": "2026-06-17",
  "total_verifications": 1280,
  "successful": 1205,
  "success_rate": 0.9414,
  "total_cost": { "amount": 712.5, "currency": "RUB" },
  "by_method": { "reverse_flash_call": 900, "telegram": 200, "sms": 120, "flash_call": 60 },
  "by_status": { "verified": 1205, "expired": 60, "failed": 15 },
  "daily": [
    { "date": "2026-06-16", "total": 95, "verified": 90 },
    { "date": "2026-06-17", "total": 60, "verified": 57 }
  ]
}
```

Что с этим делать:

- `success_rate` — доля подтверждённых проверок. Падение показывает проблемы в воронке.
- `by_status` — разбивка по причинам. Много `expired` — пользователи не успевают подтвердить (увеличьте `expiry_seconds` или упростите подсказку); много `failed` — стоит разобраться с конкретными случаями.
- `by_method` — какие методы используются.
- `daily` — для графиков по дням (дни без активности опускаются).

Параметры `from` и `to` необязательны: без них вернётся диапазон по умолчанию.
