# Частые вопросы

## Общее

### Что делает Verificahub?
Подтверждает, что номер телефона принадлежит пользователю. Вы инициируете проверку через API, пользователь совершает действие (звонок или ввод кода), и вы получаете подтверждённый номер.

### Какие методы подтверждения доступны?
Активны: `reverse_flash_call`, `flash_call`, `telegram_otp`, `sms`. Метод `voice` (голосовой код) — скоро. Методы `max_bot` (код в мессенджере MAX) и `mts_id` (подтверждение оператором МТС «Мобильный ID») доступны, если подключены для вашего аккаунта. Полное сравнение и тарифы — в разделе [Методы и тарифы](./guides/methods.md).

По способу подтверждения методы делятся на два типа:

- **Автоматический** — `reverse_flash_call`: пользователь сам звонит на выданный номер, подтверждение без ввода кода.
- **С вводом кода** — `telegram_otp`, `sms`, `flash_call` (и `max_bot`, если подключён): пользователь вводит код, вы подтверждаете его через `POST /v1/verify/check`. У `flash_call` код — это последние цифры входящего номера; у `max_bot` код приходит в MAX после того, как пользователь поделится номером в боте.

### Как подключиться?
Оставьте заявку на [verificahub.ru](https://verificahub.ru), получите доступ и API-ключ в личном кабинете — см. [Быстрый старт](./start/index.md).

## Запросы к API

### Какой базовый адрес API?
`https://api.verificahub.ru/v1`.

### Как авторизоваться?
HTTP Basic: пара `api_key:api_secret`. В curl — флаг `-u api_key:api_secret`. Передавайте их только с сервера, не из клиентского кода.

### В каком формате передавать номер?
В формате E.164, например `+79991234567`. В ответах номер тоже нормализуется к E.164.

### Что такое `request_id`?
Идентификатор сессии проверки. Возвращается при инициировании и используется, чтобы узнать статус (`GET /v1/verify/{request_id}`) или проверить код.

### Сколько живёт сессия проверки?
Срок задаётся параметром `expiry_seconds` при инициировании (если не указать — применяется значение по умолчанию). Точное время окончания приходит в поле `expires_at`. После него статус становится `expired`.

### Как узнать, что номер подтверждён?
Для `reverse_flash_call` опрашивайте `GET /v1/verify/{request_id}`, пока `status` не станет `verified`. Для методов с вводом кода (`telegram_otp`, `sms`, `flash_call`, `max_bot`) подтверждение возвращается сразу в ответе на `POST /v1/verify/check`.

### Нужно ли вызывать `/v1/verify/check` для обратного flash-call?
Нет. При `reverse_flash_call` подтверждение происходит автоматически по входящему звонку. `/v1/verify/check` нужен только для методов с вводом кода (`telegram_otp`, `sms`, `flash_call`, `max_bot`).

## Тарифы и оплата

### Сколько это стоит?
Оплата pay-as-you-go, по тарифу метода. Цена фиксируется при инициировании (поле `cost`), а фактическое списание зависит от метода (см. «Когда списываются деньги?»):

| Метод | Цена |
| --- | --- |
| `reverse_flash_call` | 0,25 ₽ |
| `flash_call` | 0,80 ₽ |
| `telegram_otp` | 0,90 ₽ |
| `max_bot` | по тарифу аккаунта |
| `sms` | 3,00 ₽ |
| `mts_id` | 2,00 ₽ |
| `voice` | скоро |

Цены ориентировочные; актуальные тарифы — на [verificahub.ru](https://verificahub.ru).

### Когда списываются деньги?
Цена фиксируется при инициировании и возвращается в поле `cost`, но **фактическое списание зависит от метода**:

- `reverse_flash_call` — только при успешном подтверждении (`verified`); статусы `expired` и `failed` **не тарифицируются**;
- `sms`, `flash_call`, `max_bot` — по факту доставки (отправки кода/звонка); недоставленные проверки не тарифицируются;
- `telegram_otp`, `mts_id` — за попытку в момент инициирования.

Так, для `max_bot` пользователь, который не открыл бота или не поделился номером, не тарифицируется.

### Что будет при нулевом балансе?
Инициирование вернёт ошибку `402`. Следите за балансом через `GET /v1/balance` — см. [Баланс и статистика](./guides/balance_and_usage.md).

### Где смотреть статистику и расходы?
`GET /v1/usage` — сводка за период: число проверок, конверсия, разбивка по методам и статусам, затраты.

## Ошибки

### Что значат статусы `expired` и `failed`?
`expired` — пользователь не успел подтвердить до конца сессии. `failed` — подтвердить не удалось. Подробнее — в разделе [Статусы и ошибки](./guides/errors_and_statuses.md).

### Получаю `401` — в чём дело?
Неверные `api_key` или `api_secret`, либо они не переданы. Проверьте учётные данные и способ авторизации (Basic).

### Получаю `400` при проверке кода (Telegram / SMS / Flash Call).
Код неверный или сессия истекла. Покажите пользователю сообщение и предложите запросить код заново.
