Раздел описывает процессы, обеспечивающие поддержание жизненного цикла программного обеспечения:
устранение неисправностей, выпуск обновлений, совершенствование, резервное копирование и
требования к персоналу.

---

## 1. Общая организация

Программное обеспечение предоставляется по модели SaaS: оно размещено на инфраструктуре
правообладателя, и поддержание жизненного цикла выполняется правообладателем. Заказчик ничего не
устанавливает и не обновляет.

Разработка, сопровождение и эксплуатация ведутся правообладателем, без привлечения иностранных
юридических и физических лиц.

## 2. Устранение неисправностей

### 2.1. Приём обращений

| Канал | Адрес |
| --- | --- |
| Электронная почта | support@verificahub.ru |
| Телефон | +7 927 938-35-62 |

Каждый ответ программного обеспечения содержит идентификатор запроса `trace_id`. Указание его в
обращении позволяет найти обработку в журнале без дополнительных сведений.

### 2.2. Порядок работы с обращением

1. Приём и подтверждение регистрации обращения.
2. Воспроизведение обстоятельств по журналу и состоянию данных.
3. Локализация: относится ли неисправность к программному обеспечению, к абонентскому устройству
   или к сети оператора связи.
4. Устранение: исправление вносится в исходный текст, сопровождается автоматическим тестом и
   выпускается в составе обновления.
5. Уведомление заказчика о результате.

### 2.3. Сроки реакции

| Приоритет | Что это | Срок реакции |
| --- | --- | --- |
| Критический | подтверждения не выполняются ни для одного заказчика | 4 рабочих часа |
| Высокий | не работает отдельный способ подтверждения либо отдельный заказчик | 1 рабочий день |
| Обычный | частная неисправность, обходной путь существует | 3 рабочих дня |
| Низкий | замечание к удобству, предложение | по мере возможности |

Срок реакции — время до начала работы над обращением. Срок устранения зависит от существа
неисправности и сообщается после локализации.

## 3. Обновление

Обновления выпускаются по мере готовности изменений; плановых сроков нет. Исправления критических
неисправностей выпускаются вне очереди.

Порядок выпуска: изменение сопровождается автоматическими тестами, выполняется их полный прогон,
изменения схемы базы данных оформляются миграцией, обновление разворачивается заменой контейнера,
после чего проверяется готовность и обслуживание запросов.

Обновление не требует действий заказчика: он не устанавливает программное обеспечение, а
совместимость программного интерфейса сохраняется. Изменения, затрагивающие интерфейс, публикуются
в [истории изменений](/docs/changelog) до вступления в силу.

---

## 4. Совершенствование

Направления развития определяются по обращениям заказчиков, показателям работы — доле состоявшихся
подтверждений по способам, операторам связи и устройствам — и изменениям в требованиях операторов
связи и законодательства.

---

## 5. Резервное копирование и восстановление

Данные размещены на дисках узла и переживают пересоздание контейнеров при обновлении. Резервная
копия базы данных создаётся средствами системы управления базами данных; восстановление выполняется
из файла копии в чистый экземпляр, после чего серверная часть применяет миграции при запуске.

Исходный текст хранится в системе контроля версий.

---

## 6. Персонал

Для поддержания жизненного цикла достаточно одного специалиста, совмещающего роли разработчика и
администратора:

| Область | Требование |
| --- | --- |
| Платформа разработки | .NET, язык C# |
| Базы данных | PostgreSQL, язык SQL, миграции схемы |
| Среда исполнения | Linux, контейнеризация |
| Сеть | HTTP, обратный прокси-сервер, TLS |
| Клиентская часть | TypeScript, сборка одностраничных приложений |
| Мобильная платформа | Android — для программного обеспечения устройства-шлюза |
| Телефония | работа SIM-карт, определение номера вызывающего абонента, ограничения операторов связи |
